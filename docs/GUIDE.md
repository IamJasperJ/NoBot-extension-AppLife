# 应用生活 / App Life

给角色一段「有日子的生活」：她按自己的作息醒来刷 B 站和抖音（各自在设置里开关），真的看懂视频（字幕、弹幕热区、热评，还能抽帧看画面），
挑值得的分享给你，写一封给你的信和一本只属于她自己的日记。你在 B 站或抖音私信她，她也会回。

灵感和风控逻辑来自 [dsh-bili-whale](https://github.com/Alterssss/dsh-bili-whale)（MIT，见 [`NOTICE.md`](../NOTICE.md)）；评分和分享机制是本扩展自己的。
人设、记忆、推送这些 NoBot 已经有了：她的人设就是角色卡，她选择绑定会话渠道分享的视频、转述的私信会进「绑定会话」，这个会话再绑到 Telegram / QQ 就能在手机上收到分享；抖音私信的回复只发回抖音，不转发到任何绑定渠道。
绑定会话可以是新建的，也可以是这个角色已有的聊天，随时在「今天」页右上角「更换」。

框架与平台分开：`core/` 是作息、风控、分享策略、日记这些通用部分，`apps/bilibili/`、`apps/douyin/` 是适配器。以后接别的应用只加一个适配器。

两个平台同时开着时，每次醒来按名额平分（5 条就是 3 + 2），各自取推荐、搜索、读、打分，再一起排心动值决定分享；
口味、分享门槛、信和日记、近期记忆两边共用，日记和历史里标着来自哪边。一个平台被风控暂停，只跳过它自己。

## 一天怎么过

| 步骤   | 做什么                                                                                                                              |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| 醒来   | 作息窗口按次数等分时段，每次在可用时段内随机取点，并遵守最小间隔；错过的时段不补，默认 30% 概率本次不想看                           |
| 不想看 | 在绑定会话里说一声为什么，照样写日记                                                                                                |
| 选片   | 推荐 + 按偏好和兴趣搜索；按你的口味、她的兴趣、新鲜度、热度排序，另留约 20% 名额给口味之外的视频（「探索」），同一个 UP 主最多 2 条 |
| 粗读   | 选出的视频（默认 5 条，最多 30）只读文字（字幕、弹幕热区、热评），便宜                                                              |
| 深读   | 最好的几条（默认 2，最多 10）再抽帧九宫格给看图模型看                                                                               |
| 打分   | 她给三项打分：自己多喜欢、你会不会喜欢、多想马上告诉你；合成 0–100 的「心动值」，再按你的 👍 / 👎 口味微调                          |
| 分享   | 心动值过了门槛才分享（见下），每天默认最多 3 条（最多 20）；同一个视频只分享一次，同一个 UP 主一天只分享一次                        |
| 写信   | 给你的信只放在「日记」页，不发到会话里；差一点没分享的视频会在信里顺口提一下                                                        |
| 日记   | 她自己的日记只存在扩展里，「日记」页可以看                                                                                          |

**分享到哪**（设置 →「分享」）：默认只在绑定会话里说。也可以选「评论区 @ 主人」（只发一条适合公开的短评，开头真正 @ 你：B 站按 mid 和「主人 B 站昵称」，抖音按 sec_uid 自动查昵称）
或「私信给主人」（只私信给你：B 站发送简短正文和链接到主人 mid；抖音优先发送原生视频卡片，再补一句话到主人 sec_uid）。B 站和抖音的分享渠道分开设，三种渠道互斥：私信和评论区分享不会在绑定会话里发言，共用同一个每日上限。确定投递失败（包括评论闸拦截和生成为空）会释放名额，并停止本轮后续分享；发送结果不确定则保留名额，避免重复发送。

**疑似 AI 评论检查**（默认关，只对评论区分享）：发评论前抽 20 条热评和最新评论让模型逐条判断，接近阈值再补到 40 条；
疑似 AI 发言占比达到 30%（写死）就不发这条评论，在绑定会话里说明原因。样本不足 20 条时照常发。结果缓存 6 小时。
这只是模型对这一批评论的估计，不是对任何人身份的鉴定。

**分享门槛**：基础门槛默认 60（设置里可调），然后自动浮动——

- 你在绑定会话里说话或私信她以后，等你说完（约 3 分钟），扩展会让模型判断你的话接没接她分享的那条：聊了内容、问了、说看了 / 想看 / 不想看都算「有回应」；只是在聊别的事不算。消息里带了 BV 号或标题片段就直接算，不用问模型。判断连续失败 3 次就退回「说话就算回应」
- 点 👍 / 👎 只算对那一条的回应
- 24 小时后还没回应：这段时间你出现过就记「没回应」，你根本没出现就记「没看到」
- 看最近 10 条（「没看到」不算，你不在不怪你）：回应多，门槛最多降 15；常被忽略，门槛最多升 15
- 当天每分享一条，门槛再 +5，越往后越挑剔
- 连续 5 次分享都没回应（含「没看到」）就进入「安静」：只写信、不主动分享；你一出现就恢复（次数可调，0 表示不启用）

**口味怎么学**：她看视频时会从标题里挑 1–4 个话题词（历史页里的 `#话题`），连同 UP 主一起记进偏好——

| 你的反应       | 学到什么                                                           |
| -------------- | ------------------------------------------------------------------ |
| 👍 / 👎        | 这个 UP 主和话题词记进「喜欢」/「不喜欢」，分量最重                |
| 回应了她的分享 | UP 主和话题词在「喜欢」里加一点                                    |
| 出现了但没理   | 只把「喜欢」里对应的分量减一点，不会记成「不喜欢」（你可能只是忙） |
| 没看到         | 不学                                                               |

学到的话题词也会成为她下次去搜的词。「视频 → 偏好」里可以直接改。

## 有人找她

| 来源              | 默认               | 怎么回                                                                                                                              |
| ----------------- | ------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| 你的 B 站私信     | 开，60 秒一轮      | 转进绑定会话，她回的话再发回私信                                                                                                    |
| 评论区回复 / @ 她 | 关，5 分钟一轮     | 你 → 直接回；别人 → 先写草稿，在「今天」或「视频 → 互动」里由你发送 / 改后发送 / 丢弃。同一个人 30 天只回一次，每天最多写 10 条草稿 |
| 直播间弹幕        | 关，填了房间号才开 | 只回你（可改成「你 + @她的人」）；每轮最多回一条，每天最多 10 条，弹幕最长 20 字。启动时把已有弹幕当已读，不补回旧的                |

监听只在作息窗口里进行，打开「全天监听」后全天都听。评论正文一律回读楼层（B 站通知里的正文字段不可靠），回读不到的会重试三次后放弃。

## 风控（照搬 bili-whale，默认按新注册的小号设置）

| 项                       | 默认                                                      |
| ------------------------ | --------------------------------------------------------- |
| 请求间隔                 | 1500 ms，全局排队                                         |
| 读取预算                 | 600 / 小时，3000 / 天                                     |
| 写入预算                 | 12 / 小时，30 / 天；两次写之间至少 120 秒；私信冷却 60 秒 |
| 撞到 412 / 429 / -352 等 | 全局暂停 5 → 10 → 20 → 30 分钟，遵守 Retry-After          |
| 登录失效 / 验证码        | 停止一切请求，等你处理后在「今天」页点「已处理」          |
| 写操作结果不确定         | 不自动重发，由你核查后选「已发出 / 没发出」               |

计数存在扩展数据里，重启不清零。老号可以在「设置 → 风控」里调大，但有下限（间隔 ≥ 500 ms，写冷却 ≥ 30 秒）。

**它不会**：给陌生人发私信、关注、投币、三连、发动态、批量操作、绕过风控。私信只发给你（设置里的 `ownerId`），而且必须互相关注。
回复陌生人的评论一定先经过你审核；公开发言不提你的隐私、账号或私聊内容。

## 浏览器后端

抖音设置新增 `douyinBrowserBackend`：默认 `headless`（原有服务器 Chromium），或 `chrome`（我的 Chrome）。Chrome 模式通过本机安装的通用「NoBot 浏览器桥」驱动插件自己的专用标签，使用用户 Chrome 的现有登录态；无需在服务器安装 Chromium。插件离线或暂停时跳过本轮，绝不自动回落到服务器 IP。`phone` 只在类型上预留，本次未实现。

插件可以从应用生活页面「依赖体检」卡片下载 ZIP，解压后在 Chrome 开发者模式中「加载已解压的扩展程序」，选择 `nobot-chrome-<版本>/`。下载接口为 `GET /api/ext/app-life/chrome/extension.zip`；`GET /api/ext/app-life/chrome/extension` 返回 `{ version: string }`，版本来自插件 manifest，每次请求重新读取。前端下载按钮由页面作者接入。

安装、配对、安全模型、接口返回结构及已知限制见 [Chrome 插件 README](../chrome/README.md)，版本化协议见 [PROTOCOL.md](../chrome/PROTOCOL.md)。前端的配对和状态界面尚需接入这些接口；插件弹窗可完成配对、暂停、白名单管理和撤销。

Chrome 模式在专用标签中正常登录后点「用浏览器里已有的登录」。验证码在 Chrome 完成；「查看页面」与「远程输入」接口会聚焦真实标签并返回 JSON，「重开」关闭旧专用标签再开新页。退出 NoBot 只清自己的凭据，Chrome 里的抖音登录不受影响。空闲默认 60 秒 detach，标签保留。

下文无头浏览器安装、代理、截图输入和扫码登录说明针对 headless 后端；Chrome 的私信图片优先在网页中读取字节，后台截图不可用时也可尝试继续。

## 抖音和 B 站有什么不同

|            | B 站                             | 抖音                                                                                                                                                                                                                      |
| ---------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 怎么请求   | 普通 HTTP 接口（WBI 签名自己算） | 接口必须由抖音自己的网页签名，所以在**无头浏览器**里打开抖音，在页面里发请求                                                                                                                                              |
| 要装什么   | 不用                             | 「今天」页点「安装浏览器组件」：从 Debian 源下载 Chromium（约 190 MB，解压约 570 MB）到数据目录，不用 root，重建容器不丢；本机有 Chrome 时直接用                                                                          |
| 看懂视频靠 | 字幕、弹幕热区、热评、画面       | 文案和话题、热评、配乐、画面（视频抽帧；图文直接拼原图）；少数视频有自动字幕                                                                                                                                              |
| 登录       | 扫码 / 粘贴 SESSDATA             | 扫码（无头浏览器里截登录框的二维码）/ 粘贴整段 Cookie（要有 sessionid）；新设备扫码后抖音还会要一次短信验证码，在「扫码登录」卡片里点「发送短信验证码」再填上；二维码过期但浏览器其实已登录时，点「用浏览器里已有的登录」 |
| 私信       | 接口                             | 操作网页私信页：按主人的 `sec_uid` 认人（同名不猜），发完回读「我发的」确认；主人得先和这个号聊过一句                                                                                                                     |
| 评论区     | 接口                             | 页面里发，先打开视频页；没拿到评论 id 算「结果不确定」，不重发                                                                                                                                                            |
| 直播弹幕   | 支持                             | 不支持                                                                                                                                                                                                                    |

抖音的额外规矩（参考 [dsh-douyin-watch](https://github.com/miqian-nomad/dsh-douyin-watch) 等，见 [`NOTICE.md`](../NOTICE.md)）：
公开评论不超过 100 字，不带网址、电话、微信等站外联系方式，同一句话对同一楼 7 天只发一次；
浏览器里弹验证码或登录失效就停手，「今天」页可以「看一眼页面」，通常重新扫码就能解除；
抖音私信只在抖音里回复，不会转发到 QQ、Telegram 等绑定渠道。主人发送的图片会从私信网页中截图作为附件，使用视觉模型时她能看到（每条私信最多 4 张，单张不超过 5MB；截图失败时保留「[图片]」占位）。私信回复仍为纯文字，暂不支持她发图或发表情包；分享视频则优先使用抖音原生卡片。

抖音私信分享会打开视频页，滚动到分享按钮并悬停，等「分享给朋友」面板出现。联系人只按 React fiber 中的 `user.sec_uid` 与主人 `sec_uid` 完全匹配，不按昵称猜人，也不会选择角色自己的账号。点击主人的「分享」后，只有同一收件人的按钮变为「捎句话」才确认卡片发出，再补一句简短文字（不带链接、不重复标题）。补充文字失败会记录活动，但视频仍算已分享。

浏览器不支持鼠标、面板未出现、主人不在列表或按钮不可用等明确未发送情形，会记录原因并回退为「正文 + 换行 + 视频链接」；主人不在列表时，请先在抖音里和角色账号聊过。点击后无法确认或连接异常会按结果不确定保留分享名额，不重发卡片，也不补发文字。卡片和补充文字各计一次私信写操作，共用冷却和预算。结束后鼠标移到页面角落收起面板，下次读私信时再打开会话页。

私信至少 2 分钟、评论通知至少 5 分钟检查一次，浏览器空闲 5 分钟自动关掉省内存。

抖音分组的「浏览器代理」可单独设置此浏览器的出口，例如 `socks5://192.168.1.20:1080`。
支持 `socks5://`、`socks4://`、`http://`、`https://`，必须填写主机和 1–65535 的端口，不支持认证、路径、查询或片段；无效值按留空处理。
留空保持原有行为；显式代理优先于容器的 `HTTP_PROXY` / `HTTPS_PROXY`，不影响 B 站或服务端其他请求。
保存代理变更后，下次使用浏览器前自动重启（清空也会重启），不会立即打断正在执行的任务。
SOCKS5 的域名由代理解析。「运行体检」会从服务端尝试连接代理端口，3 秒超时；仅确认 TCP 可连接，不验证代理协议或出口 IP，也不额外打开网页。

## 安装

1. 复制本目录到 `<DATA_DIR>/users/<账号 handle>/extensions/app-life/`，或在扩展页「从 Git 安装」。
2. 扩展页「重新扫描」，确认权限（后台任务、访问 B 站和抖音域名）并启用。
   - 网络清单包括：B 站接口和 CDN；抖音网页、短链、视频 / 图片 / 字幕 CDN；抖音页面加载的字节系资源和验证码页；安装浏览器组件时的 Debian 软件源（`deb.debian.org`，构建镜像时换了 `DEBIAN_MIRROR` 就以实际镜像为准）。
   - 抖音接口在扩展自己启动的 Chromium 页面里请求，页面还会按需加载清单外的第三方资源；宿主目前只展示这份清单，不拦截请求。
3. **设置**：选角色（她是谁）、打开要刷的平台（B 站 / 抖音）、填你的 B 站 mid、「主人抖音账号」（推荐填分享主页的链接，也可填主页链接、抖音号或 `sec_uid`）和 B 站昵称、调作息窗口、选看图连接。
4. 开了抖音的话，**今天**页先点「安装浏览器组件」，等它装完。
5. **今天**页底部每个平台一组「账号」：扫码登录（扫给角色用的那个号），或手动粘贴凭据；点「运行体检」确认登录态、浏览器和 ffmpeg。
6. **今天**页顶部：新建或指定绑定会话（之后可随时「更换」）。想在手机上收到她的消息，用渠道扩展把这个会话绑到 Telegram / QQ。
7. 想马上看她跑一轮：「今天」页点「立即醒一次」。

新版 NoBot 中，后台检查使用宿主统一任务列表：「应用生活」每 60 秒检查日程、回应与周报，「应用生活私信」每 15 秒检查私信、评论与直播（各平台仍遵守自身轮询间隔）。启用后约 1 秒进行首次检查；可在 NoBot 任务列表中暂停或手动执行，并查看执行状态。暂停会向正在执行的一轮发出取消信号。NoBot 服务需要保持运行；旧版宿主仍使用插件内置定时器，启动时立即检查一次。

## 页面

- **今天**：计划、今日分享、当前门槛和回应率、每个平台的风控用量和暂停提示、监听状态、待审回复、浏览器组件、各平台账号与登录、依赖体检
- **日记**：给你的信 / 她的日记 / 每周回顾
- **视频**：「看过的」（心动值，悬停看三项分数；理由、是否探索、分享到哪、你有没有回应、AI 检查结果，点 👍 / 👎 表态）、「互动」（待审回复和最近的评论 / 弹幕 / 分享记录）、「偏好」

## 依赖

- **ffmpeg**（可选）：只有「抽帧看画面」要用。Docker 镜像已自带；本机运行时装进 PATH 或设置环境变量 `FFMPEG`。没有也能跑，只是少看画面。
- **看图连接**（可选）：深读时把九宫格发给支持看图的模型。
- **浏览器**（只有抖音要）：见上面「抖音和 B 站有什么不同」。
### 家会话里的工具

工具只在绑定的家会话、角色一致且对应平台已启用并登录时提供。设置中的「B 站」「抖音」分组各有一个总开关「交互使用应用」，打开后才显示并生效下面的细分开关；B 站工具前缀为 `bili`，抖音为 `douyin`。需要在宿主开启工具调用。

| 工具                                | 对应开关             | 行为与限制                                                                                                                                                                                                                        |
| ----------------------------------- | -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bili_search` / `douyin_search`     | 自己逛（默认开）     | 搜索，最多返回 5 条                                                                                                                                                                                                               |
| `bili_watch` / `douyin_watch`       | 自己逛               | 阅读作品，支持链接、作品 id、分享文字；`look` 可看画面                                                                                                                                                                            |
| `bili_feed` / `douyin_feed`         | 自己逛               | 推荐流，`limit` 为 1–10，默认 6                                                                                                                                                                                                   |
| `bili_comments` / `douyin_comments` | 自己逛               | 读取评论，`sort` 为 hot/new（默认 hot），`limit` 为 1–20（默认 10），每条文本最多 200 字                                                                                                                                          |

## 数据存在哪

除了抖音的浏览器，不单独写文件，都存在你这个账号的数据库 `<DATA_DIR>/users/<handle>/app.db` 里（`settings` 表，键名 `extdata:app-life:<名字>`，值是 JSON）：

| 键                                  | 内容                                                                  | 保留                     |
| ----------------------------------- | --------------------------------------------------------------------- | ------------------------ |
| `diary`                             | 给你的信、她的私人日记、每周回顾                                      | 最近 365 篇              |
| `history`                           | 看过的视频、心动值、观后感                                            | 最近 3000 条             |
| `shares`                            | 每条分享和你的回应结果                                                | 最近 500 条              |
| `prefs`                             | 从 👍 / 👎 和分享回应学到的口味                                       | 喜欢 / 不喜欢各 200 项   |
| `ownerMessages`                     | 等待判断「有没有回应分享」的你的消息                                  | 最多 50 条，判断完就清空 |
| `<平台>:activity` / `<平台>:drafts` | 评论、弹幕、投递记录 / 待审草稿（按平台分开，私信、评论监听状态也是） | 300 / 50 条              |
| `cred:bilibili` / `cred:douyin`     | 登录凭据（抖音是整段 Cookie）                                         | —                        |

抖音的浏览器放在 `<DATA_DIR>/users/<handle>/app-life/`：`browser/`（安装的 Chromium，「今天」页可以卸载）、`douyin-profile/`（浏览器的登录态）。

信和私人日记都只在扩展数据里，不会发到会话中，「日记」页能看能删。

**她怎么记得这些**：在绑定会话里每次回复前，扩展会把一份「近期生活记忆」注入提示词（设置 → 日记 →「注入近期生活记忆」，默认开）：
最近一封信的全文（她可以自然提起）、最近一篇私人日记（只影响心情，不会念出来）、近 3 天看过的视频（标题、一句观后感、有没有分享、你怎么回应的），
以及最近几周的「每周回顾」（每周一用她自己的口吻把上周压缩成 150 字以内一段，「记住几周的摘要」默认 2，0 表示关闭）。
已分享的视频会标记实际分享渠道，方便她接上你提起的话题。四部分共用「记忆注入字数上限」（默认 2000 字），装不下时先丢最旧的每周回顾，再丢最旧的观看记录。只对绑定会话生效，其他会话看不到。备份 `app.db` 就连同这些一起备份了。

## 两个号的问题

私信专线需要两个不同的 B 站号（她的、你的）并且互相关注。只有一个号时，分享走绑定会话（默认），推送靠渠道绑定，一样能用。

浏览器组件会一并安装中文字体；旧安装可在「今天」页点击「补装中文字体」，完成后浏览器会重启。截图支持用户直接点击和拖动，可亲手处理滑块验证；扩展只按记录的坐标和时间转发操作。


「主人抖音账号」会自动换算为抖音内部使用的 `sec_uid`，评论 @、私信、评论通知认人和分享投递都使用换算结果。「今天」页的抖音账号区域会显示主人已识别（搜索找到昵称时一并显示）或失败原因。

- 分享短链支持最多 5 次跳转；`/user/self` 依赖当前登录账号，不能用来识别主人，请改填主页分享链接。
- 抖音号通过角色已登录的浏览器搜索，只接受 `unique_id` 或数字 `short_id` 完全匹配（忽略大小写及开头的 `@`），不会猜相似账号。纯数字输入也按抖音号查找，查不到时请改填主页分享链接。
- 换算结果保存在扩展存储 `douyin-owner`，输入不变就复用，改输入后重新识别。失败后同一输入 30 分钟内不重试；未登录或请求保护暂停时暂不搜索抖音号，恢复后即可识别，直接主页链接和分享短链仍可解析。未识别时不会把原始输入当作 `sec_uid` 发给平台。

抖音验证码会触发人工暂停：每次页面脚本执行前、页面脚本命令超时后，以及导航到页面后，都会用独立的 5 秒短超时执行同步 DOM 检测。检测仅认可见且宽高都大于 50 的验证码 iframe / 容器，隐藏的 `rmc-nocaptcha` 不算；检测失败不影响原流程。暂停时私信、评论、直播轮询和醒来停止使用平台，浏览器继续保活。请在应用生活里「看一眼页面」处理验证码，再点「已处理」；如果验证码仍在，下次使用会再次暂停。发送私信后才遇到验证码时，还会保留发送结果待核查记录，避免重复发送。


「看一眼页面」的点击 / 拖动回放前，会用独立的 3 秒超时探测当前页是否能收到鼠标移动事件（等待 100ms）。线上曾出现 CDP 输入命令成功、页面脚本和截图正常，但 DOM 完全收不到输入的情况，根因尚未明确。探测计数为零或探测失败时，会自动新建标签页，复用 UA、STEALTH 和时区初始化后打开原 URL（空白页使用抖音首页），关闭旧标签页并返回新截图。换页后原截图坐标已失效，因此这次点击 / 拖动不会回放，请根据新截图重新操作。新页面遇到验证码仍照常返回截图。

也可以调用 `POST /browser/reopen` 直接重开当前页，返回 `image/jpeg`；浏览器未运行时会启动并打开首页后截图。重开、输入和截图共用串行队列，等待已有后台页面任务结束后才执行。

抖音原生分享面板的最近联系人里没有主人时，会优先用主人设置中的抖音号、再用缓存昵称搜索；只有搜索结果的 sec_uid 与主人一致才会发送。
